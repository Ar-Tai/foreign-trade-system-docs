# API 契约草案

本目录包含 [OpenAPI 3.1.1 契约](openapi.json)，用于设计评审、客户端类型生成和后续契约测试。版本号是本文件采用的规范版本，不声称是最新 OpenAPI 版本。默认服务器 `https://api.example.com/v1` 仅为示例域名，没有部署服务。

## 已描述和未描述

核心范围包括品类、商品、客户、询盘、报价流转、销售订单、库存预留、出运、账款、收款核销、上传申请及集成事件。其余模块的管理列表、复杂审批配置、采购生产、售后、完整门户和报表接口需要按模块需求继续补齐；不要据此宣称 18 个模块的所有接口都已完成。

## 统一规则

- API 从认证上下文取得租户；公共请求体没有可写 `tenant_id`。
- 资源 ID 为 UUID；分页使用不透明 cursor，limit 为 1 至 100，不能将 cursor 当成授权凭证。
- 写入命令要求 `Idempotency-Key`，更新已有资源的命令还要求 `expected_version`。
- 金额和数量用十进制字符串，币种必须有明确代码和配置精度；时间采用带时区的 ISO 8601 字符串。
- 商业条件和状态只通过相应命令修改，不开放任意状态 PATCH。
- 错误采用 `code`、`message`、`request_id` 与可选 `details`。字段错误不回显令牌、收款账号或其他租户数据。

## 状态码

| 状态码 | 意义 |
| --- | --- |
| 200 | 查询或同步命令成功 |
| 201 | 创建完成 |
| 202 | 接收异步请求 不代表业务处理完成 |
| 400 | 输入格式错误 |
| 401 | 身份缺失或无效 |
| 403 | 当前主体无操作权限 |
| 404 | 资源不存在或不可见 按不泄露策略统一返回 |
| 409 | 版本 幂等或业务状态冲突 |
| 422 | 参数有效但不满足业务规则 |
| 429 | 限流 可按服务端指引重试 |
| 500 | 未预期服务错误 不暴露内部堆栈 |

## 一条调用顺序

创建客户与商品 → 创建询盘 → 创建报价 → submit → approve → issue → accept → 创建销售订单 → confirm。随后按付款计划创建应收账单、录入收款、独立复核并核销；在已满足采购及出运付款或授信条件后，获取库存 → reserve → 创建出运 → ready → dispatch。允许账期的交易，在对应到期节点继续核销并结案。

上述链路还需要已批准的质检、库存及单证数据；不存在的审批或放行结果不能由客户端自行填 true。演示 JSON 不是可直接顺序发送到真实 API 的脚本。

## 集成回调

入站集成使用连接专属的 HMAC 签名与时间戳，不使用普通用户 Bearer 认证。建议签名输入为时间戳、换行和原始请求体字节，具体编码在接入协议中冻结；常量时间比较、时间窗和事件去重必须同时实现。服务端由签名对应连接确定租户，不能采信正文中的客户或租户归属。

接口说明与模式校验依据：[OpenAPI 官方规范](https://spec.openapis.org/oas/v3.1.1.html)。
