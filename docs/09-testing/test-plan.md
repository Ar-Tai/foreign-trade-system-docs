# 测试与验收计划

## 两类测试必须分开

**文档仓库测试**现在可执行，检查链接、格式、Schema、API 契约、生成内容一致性和虚构算例。**业务系统测试**需要应用、数据库、测试账号及集成沙箱，当前仅提供用例设计，状态为 designed，尚未执行。

## 测试层次

| 层次 | 对象 | 必须证明 |
| --- | --- | --- |
| 单元 | 金额 单位换算 状态守卫 | 边界及舍入符合规则 |
| 数据集成 | 外键 事务 锁 唯一约束 | 并发不超额 跨租户不串联 |
| API契约 | 请求 响应 错误和版本 | 与 OpenAPI 和权限策略一致 |
| 端到端 | 询盘至回款及退货 | 关键事实完整闭环 |
| 安全 | 身份 文件 资源越权 事件签名 | 正反向用例均通过 |
| 性能 | 核心查询 写入 导出 | 在声明数据规模下达到目标 |
| 恢复 | 数据库 附件 队列 | RPO RTO 和一致性实际可证 |
| UAT | 真实岗位的虚构交易 | 业务人员确认可操作及口径 |

## 重点异常场景

同一报价重复转订单；两个用户同时改价；并发预留超库存；重复发运导致重复扣减；先质检冻结后发运；多次部分出运；重复银行流水；并发核销同一余额；客户转移后旧负责人导出；权限撤销后下载；消息重复乱序；恢复后再次发送付款事件；文件伪装类型；退款未到货。

## 测试数据

至少两租户、两部门、多角色客户、两仓库、跨币种成本、多批次库存、过期报价、冻结批次和未分配款项。使用 example.com 联系方式及虚构公司，不能提交真实客户或银行资料。

## 证据记录

每条业务用例记录构建版本、环境、前置数据、实际步骤、断言结果、证据链接、执行时间、执行人和缺陷编号。通过后如需求或规则变化，相关用例重新执行。72 条需求映射见[追踪矩阵](traceability.md)。

## 完成条件

关键资金、库存、租户隔离和资料泄露缺陷全部关闭；其他缺陷有明确风险接受记录；验收范围与未实现范围一致；恢复演练通过；部署和回退方案已签署。当前库中的绿色文档 CI 不能替代这些条件。
