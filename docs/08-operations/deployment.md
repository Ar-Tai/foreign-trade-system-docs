# 部署拓扑与环境管理

本页是未来应用的部署设计，不包含可运行的 Docker Compose、容器镜像或服务程序。运行仓库校验不等于启动业务系统。

## 环境

开发、集成测试、预发布和生产分离。测试环境使用虚构或经过批准脱敏的数据，禁止直接复制客户数据库供任意开发账号访问。不同环境使用不同密钥、对象存储、外部回调地址和通知接收人。

## 参考拓扑

受控入口 → 应用实例 → 私有事务数据库与对象存储；后台任务实例处理发件箱、文件扫描、导出和对账。缓存和队列不作为不可恢复的唯一账本。正式环境具备统一时间同步、证书更新、告警和日志归集。

## 配置分组

| 配置 | 示例名称 | 管理要求 |
| --- | --- | --- |
| 数据连接 | DATABASE_URL | 凭据通过密钥服务注入 |
| 对象存储 | OBJECT_STORAGE_ENDPOINT | 仅批准的服务地址 |
| 身份与会话 | OIDC_ISSUER SESSION_TTL | 与身份系统约定 不临时猜测 |
| 业务规则 | DEFAULT_REPORT_CURRENCY | 按租户配置并版本化 |
| 事件和通知 | EVENT_RETRY_LIMIT | 有上限和告警策略 |
| 文件安全 | MAX_UPLOAD_BYTES | 前后端及存储约束一致 |
| 运行观测 | LOG_LEVEL TRACE_SAMPLE_RATE | 不开启敏感载荷日志 |

## 发布顺序

备份及恢复点确认 → 数据库兼容性检查 → 应用新版本部署 → 数据迁移或后台回填 → 健康检查 → 小范围业务验证 → 放量 → 观察。数据库变更采用先扩展后收缩的兼容方式，不能假定回退程序即可回退已破坏的数据结构。

## 上线门槛

关键业务及安全用例通过；备份恢复演练达标；外部服务使用正式授权而非测试密钥；管理员账号和权限已审查；监控接收人和故障联系人明确；业务部门签署验收。当前仓库未执行这些生产条件。
