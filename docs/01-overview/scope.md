# 业务范围与产品边界

## 目标

把客户需求、供应商承诺、合同价格、货物数量、物流事实和资金核销连成可追溯链路。优先解决重复录入、报价版本混乱、库存超分配、单证不一致及收款无法对应订单等问题。

## 适用经营形态

外贸贸易公司、工贸一体企业、品牌出口团队及跨境 B2B 团队。允许接入跨境零售渠道，但本设计不是完整的消费者商城、广告投放平台或多商户交易市场。企业可以通过配置关闭不需要的生产或多仓模块。

## 纳入范围

1. 组织、角色、租户与数据范围。
2. 产品品类、SKU、规格、包装和附件版本。
3. 客户、联系人、询盘、商机、报价和样品。
4. 合同、销售订单、变更审批、分批交付。
5. 供应商、采购、生产节点、质检、库存和预留。
6. 订舱、出运、装箱、单证与关务资料协作。
7. 应收应付、收付款、核销、汇率快照及订单贡献利润。
8. 售后、门户、消息、报表、审计及外部系统集成。

## 不直接替代

专业会计总账、税务申报系统、银行支付授权、海关官方申报系统、出口管制判断、产品注册认证及法律合同审查。系统应保存这些工作的资料和结果，不把自动生成文件视为已经完成正式申报或审批。

## 版本定义

P0 表示形成核心业务闭环所需的设计范围；P1 表示扩展协作能力。优先级不是已完成状态。当前仓库版本仅交付设计与校验工具，实际排期按团队能力和明确需求重新拆分。

## 初始业务假设

- 每个租户代表独立的数据边界，可以配置多个部门和仓库。
- 一订单采用一种合同计价币种，费用与采购允许其他币种并保留原币。
- 金额和数量使用十进制定点数；规则版本、商业快照和审批结果可追溯。
- 收付款确认由财务复核，不以聊天消息或平台回调直接宣告到账。
- 示例市场、汇率、公司和金额仅用于设计演示，不代表真实经营资料。

需要确认的实际参数集中记录在[待决策事项](../10-delivery/open-decisions.md)。

品类库的覆盖范围大于首版业务启用范围。特殊监管品类不能因导入目录而自动获准经营；服务和数字产品应以交付里程碑及权益授权替代实物仓储步骤，首版是否支持这些业务需另行确认。
