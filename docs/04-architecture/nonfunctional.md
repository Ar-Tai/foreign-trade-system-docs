# 非功能目标与容量假设

以下为首轮验收建议目标，不是已测得性能。项目启动时根据订单量、SKU 数、附件大小、并发用户和部署预算重新确认。

| 维度 | 初始目标或规则 | 验证方式 |
| --- | --- | --- |
| 交互延迟 | 常用查询在明确数据规模下 P95 不超过 1 秒 | 固定数据和并发压测 不含第三方响应 |
| 写入延迟 | 核心短事务 P95 不超过 2 秒 | 记录锁等待和依赖开销 |
| 导出 | 大批量报表异步生成 可取消 有上限 | 队列压测及权限复测 |
| 正确性 | 不允许负可用库存或超额核销 | 并发测试 故障注入和账实对账 |
| 可用性 | 参考月度 99.9% 服务目标 | 明确统计窗口和排除规则后测量 |
| 恢复 | 参考 RPO 15 分钟 RTO 4 小时 | 实际恢复演练验证 不能只看备份成功 |
| 时间 | 存储 UTC 时间点 展示用户时区 | 夏令时 跨日和有效期边界测试 |
| 国际化 | 中英文名称与文件模板分离 | 多语言长度和字符集测试 |
| 可访问性 | 键盘操作 清晰标签 合理错误提示 | 人工辅助技术验证 |
| 隐私 | 最小化采集 分权查看 受控导出 | 权限矩阵和数据流审查 |

## 容量必须补齐的输入

租户数量、活跃用户、峰值并发、每天询盘与订单行数、库存批次数、文件增长率、保存期限、报表窗口和集成回调峰值。未知时不要据此承诺服务器规格。

## 限流和降级

按租户和用户对搜索、导出、文件上传和写入命令设置独立限额。外部物流不可用时保留最后更新时间和人工补录入口，不伪造实时轨迹。报表延迟时可以暂停刷新，但不能用过期读模型决定实际出库或付款。
