# M07 合同与销售订单

将获认可的报价转换为冻结商业条件的订单，建立变更、拆分交付与结案规则。

优先级：P0。角色：业务员、销售主管、财务、合规审核人。实现状态：设计。

## 业务对象与字段

对象：SalesOrder、SalesOrderLine、ContractRevision、OrderAmendment、ApprovalRequest。

关键字段：`order_no、quotation_id、customer_snapshot、currency、payment_terms、delivery_terms、line_snapshots、version`。

## 正常流程

已接受报价 → 草稿订单 → 合同与信用审核 → 确认 → 执行 → 部分交付 → 完成交付 → 财务结清 → 关闭

## 核心规则

1. 一个报价接受版本默认只生成一个订单；拆分业务需要显式关联，不允许重复点击制造重复订单。
2. 确认后价格、数量、收款主体、银行信息及交货条件变更必须生成补充协议和审批。
3. 商业状态、交付状态、结算状态分别维护，已发货不自动等于已收款或合同已关闭。

## 需求及验收

| 需求编号 | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-M07-01 | 订单来源 | 仅已接受且未失效的报价可转换；创建时保存完整商业快照。 |
| REQ-M07-02 | 确认守卫 | 必需审批、信用检查、收款条件和限制清单未满足时禁止确认，返回具体阻断项。 |
| REQ-M07-03 | 并发变更 | 两个用户用同一版本修改订单仅一个成功，另一个得到版本冲突而不是覆盖成功。 |
| REQ-M07-04 | 取消与结案 | 已有发货、资金或采购履约的订单不能简单取消，必须走剩余数量取消及退款等补偿流程。 |

## 例外处理

客户拒签时保持待确认；客户临时变更地址需要重新评估费用和运输约束。

## 指标与核查

确认周期、按时完单率、变更率、未关闭订单账龄。
