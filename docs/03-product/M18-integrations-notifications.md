# M18 渠道集成与消息通知

对接邮件、平台、ERP、物流和通知服务，采用可重放事件而非让第三方波动破坏核心交易。

优先级：P1。角色：集成管理员、业务员、系统运维。实现状态：设计。

## 业务对象与字段

对象：IntegrationConnection、ExternalMapping、InboxEvent、OutboxEvent、DeliveryAttempt、Notification。

关键字段：`connection_id、provider、external_id、event_id、payload_hash、attempt_count、next_retry_at、status`。

## 正常流程

配置连接 → 验证范围 → 接收或发送事件 → 去重校验 → 业务处理 → 重试补偿 → 对账

## 核心规则

1. 密钥放在专门的密钥管理系统，文档库、日志、前端和工单不得保存明文凭据。
2. 外部事件需验证签名、时效和去重标识；合法签名也不代表载荷中的租户字段可信。
3. 通知失败不回滚已经成功的订单或财务事务；通过事务发件箱保证后续可重试。

## 需求及验收

| 需求编号 | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-M18-01 | 回调防重放 | 错误签名、过期时间戳和重复事件分别拒绝或幂等确认，不重复产生业务效果。 |
| REQ-M18-02 | 发件箱一致性 | 业务提交与待发送事件同事务写入；发送进程崩溃后可继续处理且消费者幂等。 |
| REQ-M18-03 | 失败重试 | 瞬时故障按有上限的退避重试，永久错误进入人工队列并记录最后失败原因。 |
| REQ-M18-04 | 周期对账 | 平台订单、物流轨迹或资金映射差异可定位到原事件，重放前预览影响范围。 |

## 例外处理

第三方接口未接通时允许人工录入并标记来源；不得伪造接入成功或已收到外部确认。

## 指标与核查

事件积压、回调失败率、重试次数、对账差异、通知送达率。
