# M05 询盘商机与跟进

把邮件、展会、网站和渠道询盘转成可跟进商机，记录需求版本及响应责任人。

优先级：P0。角色：业务员、销售主管、客服。实现状态：设计。

## 业务对象与字段

对象：Inquiry、Opportunity、RequirementRevision、FollowupTask、ChannelReference。

关键字段：`source_channel、external_id、customer_id、items、quantity、target_date、target_market、owner_id、next_action_at`。

## 正常流程

接收询盘 → 解析和去重 → 分配负责人 → 澄清需求 → 评估可行性 → 报价 → 赢单或输单

## 核心规则

1. 询盘缺少产品、数量或目标市场时标记待澄清，不用默认值冒充客户要求。
2. 同一外部事件重复送达只产生一个询盘；后续邮件作为关联活动，不覆盖原始证据。
3. 商机概率用于内部预测，不等于订单收入；输单原因必须为结构化字段加说明。

## 需求及验收

| 需求编号 | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-M05-01 | 询盘幂等接收 | 同一渠道外部编号重复导入不重复创建询盘，并返回原有业务编号。 |
| REQ-M05-02 | 需求版本 | 客户修改数量或规格产生新需求版本，旧报价仍绑定旧需求。 |
| REQ-M05-03 | 响应时限 | 按租户工作日历生成待办和超时提醒，跨时区显示当地时间及原始时间。 |
| REQ-M05-04 | 商机关闭 | 赢单需关联有效订单；输单必须填写原因且可审计，重新打开保留历史。 |

## 例外处理

垃圾询盘可隔离但需保留去重标记；多负责人交接明确唯一主负责人。

## 指标与核查

首响时间、报价转化率、商机漏斗、输单原因分布。
