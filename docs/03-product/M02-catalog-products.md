# M02 品类产品与商品资料

以统一产品编码连接报价、采购、库存和售后，继承已有 80 个一级品类及 640 个二级细分作为检索起点。

优先级：P0。角色：产品经理、业务员、采购员、资料管理员。实现状态：设计。

## 业务对象与字段

对象：Category、Product、SKU、AttributeDefinition、ProductRevision、Attachment。

关键字段：`product_code、primary_category_id、name_zh、name_en、sku、specification、unit、packaging、revision、status`。

## 正常流程

选择主类目 → 补齐属性 → 建立变体 → 关联供应商 → 审核发布 → 形成版本 → 停用而不删除历史

## 核心规则

1. 品类编号不是 HS 编码；同一 SKU 只有一个主类目，其他用途采用标签。
2. 示例中的颜色、材质和规格不能自动解释成真实现货；导入资料必须有来源和审核状态。
3. 已被订单引用的版本只读，改规格生成新版本；停用产品不破坏旧订单快照。

## 需求及验收

| 需求编号 | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-M02-01 | 品类导入 | 80 个一级类目及 640 个二级类目可完整导入，重复编码和无父类目记录被拒绝。 |
| REQ-M02-02 | SKU唯一性 | 同租户 SKU 唯一；另一租户可使用同名编码而不发生数据串联。 |
| REQ-M02-03 | 规格版本 | 报价引用版本 A 后，产品更新为版本 B 不改变已发出的报价及附件。 |
| REQ-M02-04 | 批量导入 | 导入先预检并逐行返回错误，确认后提交；同一导入批次重试不生成重复商品。 |

## 例外处理

类目迁移保留旧编码映射；有历史业务的 SKU 不做物理删除；多语言名称缺失不能默默替换为错误翻译。

## 指标与核查

资料完整率、重复SKU数、规格变更次数、导入失败行数。
