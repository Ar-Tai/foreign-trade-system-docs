# M17 审批报表与审计

把审批决策、经营指标及数据导出建立在可追溯的业务事实之上，防止同一指标出现不同口径。

优先级：P0。角色：管理层、审批人、审计员、数据分析人员。实现状态：设计。

## 业务对象与字段

对象：ApprovalPolicy、ApprovalInstance、ApprovalDecision、AuditEvent、ReportDefinition、ExportJob。

关键字段：`policy_version、resource_version、submitter、approver、decision、reason、metric_definition、as_of`。

## 正常流程

触发规则 → 冻结待批版本 → 指定审批链 → 决策 → 执行受控动作 → 汇总报表 → 审计追踪

## 核心规则

1. 审批绑定资源版本；审批后资源发生重要变更，原批准不得继续复用。
2. 审计记录追加写，业务账号无覆盖删除权限；记录保留与脱敏按组织要求配置。
3. 报表必须列明币种、时间口径、过滤条件、数据新鲜度和是否含取消订单。

## 需求及验收

| 需求编号 | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-M17-01 | 审批失效 | 订单改价或改账户后旧版本审批不能用于新版本的放行。 |
| REQ-M17-02 | 指标一致 | 订单数、出运量、应收余额和贡献利润有唯一公式及排除规则，可抽样回溯。 |
| REQ-M17-03 | 导出授权 | 导出在提交和下载两个时点检查权限，限制范围、行数与敏感列。 |
| REQ-M17-04 | 审计完整 | 审批、出运、核销、权限变更和文件下载事件含行为主体、资源、时间及请求编号。 |

## 例外处理

审批人休假可经授权转交，不能静默跳过；报表缓存不能跨租户复用。

## 指标与核查

审批周期、报表延迟、导出任务失败率、审计事件缺失数。
