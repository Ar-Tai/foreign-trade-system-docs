# M01 组织身份与权限

隔离不同经营主体，按岗位、部门和数据归属控制查看与操作，避免把登录成功等同于拥有全部业务权限。

优先级：P0。角色：租户管理员、部门主管、审计员。实现状态：设计。

## 业务对象与字段

对象：Tenant、User、Membership、Department、Role、Permission、Session。

关键字段：`tenant_id、user_id、department_id、role_ids、data_scope、status、session_version`。

## 正常流程

邀请用户 → 验证身份 → 分配租户和岗位 → 设置数据范围 → 使用业务功能 → 调岗或停用 → 撤销会话

## 核心规则

1. tenant_id 由服务端已验证的身份上下文确定，不能相信请求体或可任意修改的请求头。
2. 同租户也要执行资源归属检查；财务账号不自动取得系统配置权限，管理员不默认可审批自己提交的付款。
3. 高风险操作要求二次验证；停用或角色撤销后必须使会话、导出任务及长期下载授权失效。

## 需求及验收

| 需求编号 | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-M01-01 | 租户隔离 | 用户访问另一租户的客户、附件、报表和异步任务时均被拒绝，不泄露资源存在性。 |
| REQ-M01-02 | 职责分离 | 付款申请人与付款审批人不能是同一用户，紧急例外必须经独立授权并留下理由。 |
| REQ-M01-03 | 会话撤销 | 停用账号后所有后续交互和令牌刷新失败，未完成的导出任务不再交付文件。 |
| REQ-M01-04 | 权限审计 | 角色变更记录前后值、操作者、目标用户、原因和请求编号，普通管理员不可删除记录。 |

## 例外处理

邀请过期需重新发起；人员离职先移交客户与审批任务，再停用账号；不得通过复用离职账号继承数据。

## 指标与核查

越权请求数、停用生效延迟、长期未使用权限数、权限审查完成率。
