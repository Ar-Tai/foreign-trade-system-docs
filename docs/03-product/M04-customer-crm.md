# M04 客户与联系人管理

建立客户公司、联系人、地址和跟进历史，明确客户归属、授信状态与资料访问范围。

优先级：P0。角色：业务员、销售主管、客服、财务。实现状态：设计。

## 业务对象与字段

对象：Customer、Contact、Address、Activity、CustomerAssignment、CreditProfile。

关键字段：`customer_code、company_name、country、owner_id、contact_method、billing_address、shipping_address、credit_status`。

## 正常流程

录入线索 → 去重 → 认领分配 → 联系与跟进 → 客户评估 → 成交维护 → 归档

## 核心规则

1. 公司和联系人分开，账单地址和收货地址分别版本化；订单引用的是当时确认的地址。
2. 客户去重使用规范化公司名和业务标识辅助判断，不自动合并仅因同名的不同企业。
3. 跨部门转移客户需要移交记录；客户删除和个人信息处理按实际保留要求审查。

## 需求及验收

| 需求编号 | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-M04-01 | 客户去重 | 相同标识的新客户触发人工确认，确认前不自动合并订单或联系人。 |
| REQ-M04-02 | 归属限制 | 业务员只能查看授权范围内客户，主管的跨组查看权限可独立配置。 |
| REQ-M04-03 | 地址快照 | 客户地址变更不修改已确认订单、商业发票或已生成的运输标签。 |
| REQ-M04-04 | 授信拦截 | 超出已批准账期或额度的订单不能直接确认，必须进入独立授信审批。 |

## 例外处理

公共客户池与个人客户池有独立领取规则；失联客户归档不抹除未结应收。

## 指标与核查

活跃客户数、客户资料完整率、客户转化率、逾期客户占比。
